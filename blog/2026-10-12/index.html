Daily briefing

  1. MultiAgentInject is a new security benchmark with 4,050 trials that independently varies task, agent-network topology, attack class, stealth, and propagation depth. It records whether an injected instruction reaches other agents separately from whether those agents comply, rather than collapsing both events into attack success. Why it matters: If you are evaluating multi-agent defenses, this separation helps identify whether to change communication boundaries that permit propagation or safeguards that prevent compliance after exposure. A single attack-success score cannot distinguish those decisions. Evidence: E002. High confidence.
  2. SimGlot is a new artifact for testing the benchmark harness itself—the task generator and reward function that decide whether an agent succeeded. It provides eight integrity checks and 21 injected fault variants across seven defect classes, with records binding results to frozen software revisions. Why it matters: If you maintain an agent benchmark, this offers a way to test whether scores survive known evaluator defects before using them for model selection. It shifts part of evaluation from testing agents to verifying that the scoring software supplies a trustworthy answer key. Evidence: E056. High confidence.
  3. APEX-Harm is a new prompt- and script-injection benchmark for long-running agents operating across shared professional workspaces. Its finance, consulting, and legal tasks contain 115 to 328 files and expose email, calendar, chat, documents, spreadsheets, Portable Document Format files, and code execution through tool servers. Why it matters: If you are testing workplace agents, this means defenses can be assessed when malicious material may appear anywhere in a large, changing workspace—not only at a predetermined document location. That design better distinguishes safe navigation across tools from resistance to one isolated prompt. Evidence: E024. High confidence.
  4. MisVisAgentBench is a new executable web-agent benchmark containing 280 matched pairs of clean and misleading charts. The pairing holds the task context together while changing the visualization, then measures effects on downstream agent actions rather than chart-question accuracy alone. Why it matters: If you are choosing a web-agent evaluation, matched pairs let you attribute execution changes to misleading visual evidence more directly than unrelated task sets can. The benchmark also tests whether chart interpretation errors propagate into actions, which matters for agents that act on dashboards. Evidence: E029. High confidence.
  5. CRBugBench is a new code-review benchmark built from 1,000 human-verified bugs across 98 open-source repositories. Each task pairs a bug with the pull request that introduced it, turning repository history into a review task rather than asking an agent to generate code from scratch. Why it matters: If you are deciding whether automated review can supervise agent-written code, this evaluates detection of defects that passed through real development workflows. It measures a different deployment gate from coding benchmarks: whether a reviewer catches an introduced bug before approval. Evidence: E022. High confidence.
  6. CACE-Bench is a new synthetic benchmark and generator for credit-processing agents under auditability constraints. Its regulatory-shift track separates the applicants used to admit pipeline changes from the 300 applicants evaluated per seed, and it reports admissions of candidate changes and harmful changes separately. Why it matters: If you are evaluating an agent that modifies a regulated decision pipeline, the held-out gate tests whether proposed changes generalize beyond the cases used to approve them. Separate harmful-admission reporting also supports a release decision that ordinary average performance would obscure. Evidence: E004. Medium confidence.
