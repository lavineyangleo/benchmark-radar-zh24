Daily briefing

  1. The new Curation-Bench release evaluates whether coding agents can improve training-data selection through an iterative workflow: agents inspect data, implement selection policies, run a fixed training and evaluation pipeline, observe noisy results, and revise their policies while the model and training recipe remain fixed. This isolates the agent’s data-curation decisions from unrelated model changes. [E003] Why it matters: If you are deciding whether an agent can automate data preparation, this benchmark tests the operational loop rather than asking for a one-shot policy recommendation. It can distinguish agents that merely propose plausible rules from those that improve policies using measured feedback. [E003] Evidence: E003. High confidence.
  2. The new XYEval release converts existing benchmarks into tests of whether agents resist the “XY problem,” where a user proposes a plausible but misguided solution instead of explaining the underlying need. It evaluates five models across six suites and reports performance drops after this mutation. [E016] Why it matters: If you evaluate assistants that advise users, ordinary task accuracy may miss harmful agreement with a faulty premise. XYEval provides a way to reuse an existing suite while adding a communication stress test, making resistance to misleading advice a separate selection criterion. [E016] Evidence: E016. High confidence.
  3. The new VibeMemBench release tests persistent memory—the ability to reuse prior experience—through executable work on 111 coding targets from 90 software repositories, backed by 3,634 historical trajectories. It covers bug fixes, feature requests, interface changes, and configuration work rather than scoring memory through recall questions alone. [E018] Why it matters: If you are choosing a memory system for a coding agent, this design measures whether stored experience improves completed repository changes. That separates useful memory from systems that retrieve relevant-looking history without improving the resulting code. [E018] Evidence: E018. High confidence.
  4. The new ChartJudgeBench release evaluates vision-language judges—models that inspect both images and text—used to score chart-to-code systems that recreate charts as programs. Its diagnostics include 1,003 pairwise visual-comparison cases and 650 reasoning-judgment cases. [E014] Why it matters: If model-generated judge scores drive regression tests or reward-based training, the judge itself becomes part of the measurement system. ChartJudgeBench lets teams test visual comparison and reasoning separately before treating those scores as reliable optimization targets. [E014] Evidence: E014. High confidence.
  5. The new BabelArena release extends agent evaluation beyond English with 16,146 multilingual instances derived from 702 canonical tasks. Its BabelFlow process analyzes runtime dependencies, preserves task structure during translation, and applies automated verification plus human review to retain task and scoring meaning. [E019] Why it matters: If you are selecting an agent for multilingual workflows, translated prompts alone may alter tools, dependencies, or expected outputs. BabelArena offers aligned tasks intended to support language-by-language comparisons without silently changing what the agent must accomplish. [E019] Evidence: E019. Medium confidence.
  6. The Full-text extraction pipeline for atomic layer deposition process parameters received an update that preserves its earlier frozen scorer while adding a corrected scorer for three identified defects, including comparisons of temperatures reported in kelvin without conversion. [E108] Why it matters: If you reproduce or compare results from this extraction pipeline, the scorer version is now an evaluation variable. Keeping both versions allows teams to audit earlier numbers while using corrected measurement logic for new runs instead of mixing incompatible results. [E108] Evidence: E108. High confidence.
